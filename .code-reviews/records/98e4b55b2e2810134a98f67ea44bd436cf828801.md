## Summary

Adds in-board Jira loading to ticketboard (plugin 0.7.0 to 0.7.1). The board now spawns a headless `claude -p` limited to Atlassian read tools to fetch an issue and its comments. A new **Load** button on the New ticket form and a **Refresh from Jira** link on the ticket use it. On Create, the loaded snapshot is saved with the ticket. Stack: no marker matched (plain Node.js plugin with a vanilla HTML UI), so this was a generic review covering correctness, security, consistency and maintainability, with the surrounding `store.js` Jira code read for context.

- **plugins/ticketboard/lib/store.js:1813** — The headless Claude call passes `--allowedTools` to restrict it to Atlassian read tools, but that flag only pre-approves tools. It does not remove others. Any broader allow rules in the user's own Claude settings (for example a blanket Bash allow) also apply, so the "no shell, files or Jira writes" claim in the README is not enforced. The process reads untrusted Jira text from other people, and its output is stored in the ticket description that later planning and build agents read. *(security)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fixed. The headless call now uses `--setting-sources ''`, `--permission-mode dontAsk`, a `--disallowedTools` list covering all built-in tools except ToolSearch, and the connector's write tools. The README describes this and the prompt marks Jira text as data.
- **plugins/ticketboard/lib/store.js:1845** — `jiraRefresh` overwrites the ticket's title and description with the model's rewrite, with no confirmation and no snapshot of the previous local text. The description may have been edited by the developer or planning. The only safeguard is a prompt asking the model to "keep what still holds". *(correctness)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fixed. The UI now asks for confirmation before a refresh replaces the title and description, and `update()` logs the old and new values (`from`/`to`) in the ticket history, so the replaced text is recoverable.

  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fixed. `jiraSave` is wrapped in try/catch and the route returns the ticket with a `warning`; the UI shows the warning and the form closes, so Create is not retried.
