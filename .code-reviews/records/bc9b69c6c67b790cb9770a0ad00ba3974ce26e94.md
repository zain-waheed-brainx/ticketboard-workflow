## Summary

Stack: no NestJS/React/Express/Rails/PHP/Flutter/iOS/Android marker (plain Node CLI plugin with a vanilla HTML UI), so a generic review was applied (correctness, security, consistency, maintainability).

Adds a "Run app" feature (start a ticket's dev servers in its worktree, one ticket at a time, with CLI, API and board UI), per-project Node version selection (`.nvmrc`, `.node-version`, profile `versions.node`) for setup, tests and run, Horizon detection for Laravel, a Settings field for the app URL, README docs, and a version bump to 0.6.0. The new API routes sit behind the existing Host, Origin and JSON content-type checks, and dev commands only run once the profile is trusted, so the new attack surface is small. Main concerns are the handling of common `.nvmrc` aliases and signalling stale PIDs.

### High (1)
- **plugins/ticketboard/lib/store.js:91** — `nodeFor` treats any `.nvmrc` / `.node-version` content that is not a plain number as a hard error, and `nodeEnvFor` and worktree setup turn that error into a failure. Aliases such as `lts/*`, `lts/iron`, `node` or `stable` are valid and common `.nvmrc` values.
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fixed. `nodeFor` now resolves nvm aliases (`node`, `stable`, `lts/*`, `lts/<name>`, `default`) through nvm's alias files and returns null (keeps the current node) for unknown aliases, so they no longer fail bootstrap, tests or Run app. Alias names are validated against `[\w*/.-]` and `..` before the file read.

### Medium (1)
- **plugins/ticketboard/lib/store.js:1561** — Liveness and stop logic trusts bare PIDs saved in `.board/run.json`. After a reboot or a long idle period a recorded PID can belong to an unrelated process, and `runSignal` then sends SIGTERM and SIGKILL to that process group (and falls back to killing the PID itself) *(correctness / safety)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fixed. `Board.alive` now requires the process start time (`ps -o lstart=`) to match the value saved at launch, and `runSignal` only signals the recorded process group (`kill(-pid)`) for entries that pass that check. The bare `kill(pid)` fallback is gone.

### Low (2)
- **plugins/ticketboard/lib/store.js:1580** — `runLogTail` opens a file descriptor and does not close it if `readSync` throws. It also cuts at a byte offset, so the first character of the tail can be a broken multi-byte sequence *(maintainability)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fixed. `runLogTail` closes the fd in a `finally` block and drops the partial first line when the tail is cut.
- **plugins/ticketboard/ui/index.html:376** — `setInterval(refreshRun, 3000)` polls `/api/run` forever, including while the tab is hidden, and `load()` also triggers a refresh *(maintainability / efficiency)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fixed. `refreshRun` returns early when `document.hidden`, and a `visibilitychange` listener refreshes when the tab is shown again.
